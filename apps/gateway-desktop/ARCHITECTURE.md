# Gateway Desktop — Architecture

Validation client for Gateway RFC Phase 3. Three processes, one
authority.

## Authority model

| Owner | Owns | Never does |
| --- | --- | --- |
| **Gateway** (`clinegate`) | All persistence: bots, sessions, runs, attempts, events, messages, approvals | — |
| **Broker** (`native/`, Bun) | The Gateway connection and a replaceable `DesktopProjection`; UI-safe persisted metadata + replay cursor | Read/write Gateway SQLite or session files; start/stop/upgrade/replace a Gateway; mutate without a user action |
| **Webview** (`webview/`, Next.js) | Ephemeral presentation state | Import SDK protocol packages; read env vars; see secrets, paths, or raw diagnostics |
| **Tauri shell** (`src-tauri/`) | Window + bundled Gateway/broker lifecycle + per-launch bridge secret + reveal-diagnostics | Import the Cline SDK; implement Gateway commands |

## Gateway surface used

The broker talks to the Gateway exclusively through
`@cline/gateway/client` (typed surface added for Phase 3 application
consumption): `getStatus`, `listBots`, `listSessions`, `listRuns`,
`getSession` (hydration snapshot with runs+attempts+messages+cursor
basis), `startRun`, `steerRun`, `interruptRun`, `retryRun` (same runId,
new attempt), `subscribe` (durable cursor replay), server-request
handling for approvals, and `resolveApproval`. There is no second
protocol stack in this app.

## Bridge contract (`shared/bridge.ts`)

Closed command set — no generic invoke:
`app.initialize`, `gateway.reconnect`, `bot.select`, `workspace.select`,
`session.select`, `run.start`, `run.steer`, `run.interrupt`,
`run.retry`, `approval.resolve`, `diagnostics.reveal`.

Broker → webview frames: `projection.replace`, `projection.patch`
(revision-fenced: applied only when `baseRevision` matches, otherwise
the webview requests a replace via `app.initialize`), `command.result`
(with `PublicDesktopError` on failure).

Transport: WebSocket on 127.0.0.1 only. The per-launch secret (random,
generated by the shell, passed to the broker via environment and to the
webview via the `bridge_endpoint` Tauri command) authenticates as the
FIRST frame — never in URLs, argv, or logs. Headless development uses
an explicit opt-in dev secret (`GATEWAY_DESKTOP_DEV_BRIDGE=1`).

Limits: 1 MiB per frame both ways; prompts/steer text ≤ 256 KiB; NUL/C0
control characters rejected; unknown commands rejected; message content
beyond bounds is truncated with a visible marker; the conversation
projection keeps at most 200 messages.

`clientRequestId` doubles as the Gateway idempotency key: the broker
dedupes duplicate command frames, and the Gateway's durable ledger
dedupes across reconnects — a retried command can never double-mutate.

## Projection rules (`native/gateway/reducer.ts`)

1. Hydrate wholesale from snapshots (`gateway.status`, `bot.list`,
   `session.list`, `run.list`, `session.get`), taking the cursor basis
   BEFORE the list reads so replay can only overlap, never gap.
2. Apply only contiguous events (global sequence). A duplicate is
   skipped; a gap stops application and forces reconnect + rehydrate.
3. Persist the cursor only after the event was committed locally
   (debounced write of `state.json`, 0600).
4. On reconnect: hello → verify same `gatewayId` (a different identity
   resets everything) → record the new `instanceId` → subscribe from the
   persisted cursor → hydrate snapshots → reconcile. When the replay
   distance exceeds 5000 events, incremental recovery is abandoned and
   the projection is rebuilt wholesale.
5. Workspace paths never enter the projection: the broker maps each
   root path to an opaque `workspace-<hash>` id and keeps the mapping
   private. Gateway events are treated as untrusted input (structural
   reads, bounded text, no raw HTML rendering).

## Reconnect

Backoff 250ms → 500ms → 1s → 2s → 5s → 10s cap, ±20% jitter.
`gateway.reconnect` (user action) resets the backoff. An incompatible
protocol (`protocol_version_unsupported`) is terminal — visible state,
no retry loop. Reconnection never mutates: no auto-retry of runs, no
replayed commands, and never a replacement session to paper over a
connection failure. Disconnect never implies abort (server invariant).

## Approvals

Server-initiated requests are independent of ordinary events. The
broker projects them (`ApprovalProjection`), answers through the
webview's `approval.resolve`, and the Gateway broadcasts a durable
`approval.resolved` event so every other attached client dismisses its
copy. First committed answer wins; a late local answer fails with
`approval_already_resolved`. Pending approvals survive disconnects and
are re-issued on resubscribe.

## Errors

Everything the webview sees is a `PublicDesktopError`: stable `code`,
sanitized bounded `message`, `retryable`, optional `correlationId`, and
an `action` hint (`retry` | `start_gateway` | `update_client` |
`choose_workspace` | `none`). Raw diagnostics stay in the broker's
redacted JSONL logs.

## Boundaries (machine-checked)

`native/boundaries.test.ts` enforces: webview imports no SDK protocol
package (`@cline/ui` presentation-only excepted), no `process.env`, no
`dangerouslySetInnerHTML`, no broker imports; broker production code
imports only `@cline/gateway/client` from the Gateway package and never
`@cline/core`/Hub; shared contracts import no SDK package; fixture
projections contain no paths or secret-shaped keys.

## Known trade-offs (validation-app scope)

- Live `text-delta` streaming renders only for the currently open
  session view; deltas emitted before the view opened are covered by
  canonical message history instead of a replayed live buffer.
- Queued-turn previews for runs started by OTHER clients show a
  placeholder until the next snapshot hydration.
- `projection.patch` patches whole top-level fields (e.g. the entire
  `activeSession`) rather than fine-grained paths.
